# 唐傘・参照忠実度再設計 補足仕様

**日付:** 2026-07-12
**状態:** 方向性は承認済み。本文書はユーザーレビュー待ち。
**対象:** Step 4「夜行絵巻 2.0」の唐傘 40×48 px・8フレームのみ

## 1. 目的と優先関係

ユーザー提供の参照画を、別キャラクターへ再解釈せず、SNES相当の40×48ピクセルアートへ忠実に翻訳する。識別要素は、正面を向いた赤い円錐形の傘、茶色の頭頂と金色の帯、中央の一つ目、曲線の笑い口、桃色の舌、淡色の一本足、一つの金／茶色の下駄である。

本書は `2026-07-11-yagyo-emaki-2-design.md` の唐傘アセット契約を補足する。両者が衝突する場合、唐傘の色、姿勢、輪郭、`strong` の見た目については本書を優先する。既存の状態名や reducer の `.open` という内部フェーズ名は互換性のため残してよいが、横に開いた傘や裏面を描く許可を意味しない。

現在の紫色・横向きの唐傘と、それを収めた通常、quiet、strong、丑三つ時、最小幅等のスクリーンショットは明示的に不採用・失効とする。新しい証跡に置き換わるまで、唐傘の視覚承認には使用できない。

## 2. 検討した方針

### A. 正面忠実型・小動作（採用）

全8フレームで赤い三角形と中央軸を守り、足、下駄、裾、舌、瞼だけを1〜2 px中心に動かす。参照画との同一性と行列内の読みやすさを両立できるため採用する。

### B. 誇張した squash／stretch（不採用）

状態差は強くなるが、傘幅と顔の配置が大きく変わり、参照画から別キャラクターへ逸脱しやすい。40×48では位置跳ねにも見えるため採用しない。

### C. ほぼ静止した差分（不採用）

参照忠実度は高いが、`walk 4`、`hush`、`strong 2` の振付上の意味が弱くなる。Reduce Motionとの差も読みにくいため採用しない。

## 3. 選定した参照契約

### 3.1 固定する造形

- 全フレームが正面向きで、赤い円錐形の傘布を主輪郭とする。
- 茶色の頭頂、金色の帯、一つ目、笑い口、桃色の舌、一本の淡色脚、一つの金／茶色の下駄を保持する。
- 顔、脚、下駄は傘の中央軸上に積み、左右へ別々の身体部品を追加しない。
- 参照画の素朴で親しみのある表情を保つ。怖さ、武器、柄、首、腕、複数の脚を足さない。
- 紫の傘、横顔、長い斜めの柄／首、横へ流れる赤布、蛇状の脚、巨大な横向き下駄は削除し、いずれのフレームにも再導入しない。

### 3.2 キャンバス、軸、座標帯

- キャンバスは40×48 px、`anchorX = 20`、`baselineY = 45`を維持する。
- 座標は左上を `(0, 0)` とする包含範囲。次の帯は参照姿勢を作るためのおおよその配置であり、各フレームの許容差は4章で限定する。

| 部位 | おおよその座標帯 |
|---|---|
| 全体 | `x = 3...36`, `y = 1...45` |
| 傘布 | `x = 3...36`, `y = 6...35` |
| 茶色の頭頂＋金帯 | `x = 15...24`, `y = 1...8` |
| 一つ目 | `x = 16...23`, `y = 12...18` |
| 笑い口 | `x = 14...25`, `y = 18...21` |
| 舌 | `x = 17...22`, `y = 20...27` |
| 一本足 | `x = 18...21`, `y = 34...43` |
| 下駄 | `x = 16...23`, `y = 43...45` |

偶数幅の部位は `x = 19.5` 付近を光学中心とし、配置契約の `anchorX = 20` と両立させる。完全な鏡像ではなく、左右の輪郭差を1 px以内に保つことで手描き感を許容する。

### 3.3 色と描画

- 透明を除く不透明色は最大12色。2倍の整数倍率、補間なしで表示する。
- 色群は、濃い茶色の輪郭／瞳、赤〜珊瑚色3〜4段、白〜生成りの目、桃色の舌、淡色の脚、茶／金色の頭頂と下駄に限定する。
- 傘布の赤〜珊瑚色が画面占有と色数の両方で主色となる。紫系の色値はパレット定義にもフレームにも含めない。
- 陰影は赤い三角形を分断せず、傘骨または布の折りとして中央から裾へ流す。

## 4. 8フレームの振付

既存契約 `idle 1 + walk 4 + hush 1 + strong 2` を変更しない。大きな姿勢変換ではなく、参照姿勢に対する二次動作で状態を示す。

| 状態 | 枚数 | 見た目と移動上限 |
|---|---:|---|
| `idle` | 1 | 正面の基準姿勢。赤い三角形、中央の顔、一本足、下駄を最も明瞭に示す。 |
| `walk` | 4 | contact-lock方式。下駄は全フレームで `y = 45` に接地する。下駄の軸は基準から左右最大2 px、脚は最大1 px。傘布と舌は進行方向へ1 px遅れて追従する。 |
| `hush` | 1 | 傘体を最大2 px下げ、脚を2〜3 px畳み、舌を2 px引き、上瞼を1 px下げる。正面の赤い三角形と接地は維持する。 |
| `strong` anticipate | 1 | 中央軸を保ち、縦・横とも片側最大1 pxだけ圧縮する。横へ開かず、反応前の溜めだけを示す。 |
| `strong` reaction | 1 | 裾を片側最大2 pxだけ張り、目と舌を1〜2 px強調する。正面の円錐形を保ち、幅広い水平傘、傘の裏面、横顔へ変形しない。 |

原則として二次動作は1〜2 pxに制限する。`hush` の脚の折り畳み2〜3 pxだけを明記された例外とする。歩行中も傘布の光学中心は基準から1 px以内、裾幅の差は基準から合計2 px以内とする。`strong` reactionだけは裾を左右それぞれ最大2 px広げてよいが、中心差は1 px以内かつ傘布の高さ／幅比を0.75以上に保つ。

## 5. 構造テスト要件

既存のフレーム数、40×48、`anchorX = 20`、`baselineY = 45`、透明余白、最大12色、未知記号なしのテストを残し、次を追加する。

- **赤い傘が主役:** 傘帯 `y = 6...35` の赤／珊瑚色画素数は他の有彩色群より多く、輪郭を除く傘布内の不透明画素の55%以上を占める。
- **紫を禁止:** 旧紫4色 `0x6e5aa8`, `0x3f315f`, `0x9f88d1`, `0x2b203d` を含めず、承認パレットに紫色群を設けない。
- **正面と均衡:** 傘布の左右端は光学中心に対して1 px以内で釣り合い、目、口、舌、脚、下駄の各中心は中央軸から1 px以内に置く。
- **一つ目:** 目の座標帯に白／生成りの連結成分と、その内側の濃色の瞳をそれぞれ1つだけ持つ。第二の目を作らない。
- **一本足:** 脚の座標帯から下駄へ続く淡色の連結成分を1つだけ持つ。第二の脚または蛇状に分岐する脚を作らない。
- **接地:** 全フレームで下駄の不透明画素が `y = 45` に接し、`y > 45` に不透明画素を置かない。
- **不透明bboxと輪郭ドリフト:** 全フレームの不透明bboxは下端を `y = 45`、水平中心差を`idle`から1 px以内に保つ。`walk` の傘幅差は合計2 px以内、上端の縦差は2 px以内、下駄軸は2 px以内。`hush` は下方向2 px以内。`strong` anticipateは縦・横とも片側1 px以内の圧縮、reactionは裾の片側2 px以内の拡張とする。
- **三角形を維持:** 傘布の下段の赤色spanは上段より広く、全フレームで傘布の高さ／幅比を0.75以上にする。横長のopen姿勢を構造的に失敗させる。

色のカテゴリと部位の座標帯はテスト側に同じ意味名で表し、任意のスクリーンショット比較だけに依存させない。1 pxのアンチエイリアスや非整数補間を許可しない。

## 6. 範囲と非目標

この再設計で変更してよいのは、唐傘8フレームの行文字列、唐傘パレット、およびその構造契約テストと置換後の視覚証跡だけである。

次は変更しない。

- `ParadeSignalReducer` の閾値、状態遷移、phase名、タイミング
- 再生、メータリング、Audio Session、Now Playing、resident割当
- 絵巻のレイアウト、倍率、座標補正、アクセシビリティの意味
- 唐傘以外の妖怪、背景、Step 3、DSP／Music Understanding
- `idle 1 + walk 4 + hush 1 + strong 2`、`anchorX = 20`、`baselineY = 45`

## 7. 検証と視覚承認ゲート

1. 唐傘の構造テストと既存テストを通す。
2. 全8フレームを最近傍2倍で並べたフレームシートを作り、正面、赤い三角形、一つ目、一本足、接地、1〜2 px動作を目視確認する。
3. Simulatorで通常、quiet、strong reaction、Reduce Motion、丑三つ時、resident先導、最小対応幅を確認し、切れ、補間、位置跳ね、旧妖怪との衝突がないことを確認する。
4. 旧スクリーンショット一式を、作り直した唐傘が明瞭に見える新しいリポジトリ／Draft PR上の証跡へ置き換える。旧画像を新画像と並べて承認候補として残さない。
5. ユーザーが新しい証跡を見て明示的に承認するまで、唐傘を視覚完了とせず、残りの妖怪への展開や `main` 統合へ進まない。

合格条件は、構造契約を満たすことに加え、ユーザーが参照画と同じ唐傘だと認識できることである。自動テストの合格だけでは視覚承認を代替しない。
